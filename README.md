## 🚀 What This Plugin Does

Obsidian-LLM-Plugin brings large language model chat into your Obsidian workspace. A large language model is the technology behind AI chat tools. With this plugin, you can ask questions, draft text, summarize ideas, rewrite notes, and explore topics while staying inside Obsidian.

The plugin supports local and web-based models. Web-based models use an internet connection. Local models are intended for users who want to run model software on their own computer. The plugin does not replace Obsidian. It adds chat access to the Obsidian experience through several interfaces so you can choose the one that fits your workflow.

## ✨ Key Features

The plugin provides four main ways to chat with AI:

- Modal chat: a focused pop-up chat window for quick questions and short tasks.
- Widget chat: a compact chat surface that stays available while you work.
- FAB window: a floating action button that opens a chat window for fast access.
- Commands: chat actions that can be started from Obsidian commands.

These interfaces are useful in different situations. Use the modal when you want a clean, focused conversation. Use the widget when you want chat nearby but not in the way. Use the FAB window when you want one-click access. Use commands when you prefer keyboard-driven workflows.

The plugin is designed around flexibility. You can use web-based models when you need quick access to online AI services, or local models when you prefer to work with model software running on your own machine.

## 🔒 Local and Web-Based Models

The plugin supports both local and web-based models, and the difference matters for how you work.

Web-based models send your requests over the internet to an online service. They are convenient when you have a stable connection and want fast access to a capable model. Your prompts travel over the network, so treat them the same way you would treat any online service.

Local models run through model software on your own computer. They can be a good fit if you prefer to keep model activity on your machine, or if you want to work in a way that does not depend on an online chat service for every request. Local models depend on the model software you run and the hardware you have, so performance varies from computer to computer.

You can switch between the two approaches depending on the task. A quick rewrite might suit a web-based model, while a longer working session might suit a local model you already have running.

## 🛠️ Troubleshooting Common Issues

If chat does not respond, check your internet connection first when you are using a web-based model. A dropped connection is the most common cause of a message that never finishes.

If a local model does not answer, confirm that your local model software is running and ready before you send a message from Obsidian. Start the model software first, then try the chat interface again.

If the chat window does not appear at all, restart Obsidian and look again for the modal, widget, FAB button, or command. Interface elements sometimes need a reload to show up.

If a response seems cut off or strange, try a shorter prompt. Long, complicated requests are harder for any model to handle in one pass. Break the task into smaller questions and work through them one at a time.

If Obsidian feels slow while chat is open, close chat windows you are not using. Keeping several chat surfaces open at once uses more resources than keeping one open.

## 🗒️ Tips for Getting Better Results

Be specific about what you want. Instead of "make this better," ask for a shorter version, a clearer version, or a version written for a beginner.

Give the model context. Paste the passage you want help with, or describe the audience and tone you have in mind.

Ask for one thing at a time. A single clear request usually produces a more useful answer than a long list of demands.

Review everything before you save it. AI output can be wrong, out of date, or simply not what you meant. Your notes are yours, so read before you keep.

Keep your prompts short at first. Once you see how the model responds, you can build longer requests with more confidence.
